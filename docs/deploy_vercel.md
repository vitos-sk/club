# Как выложить приложение на Vercel

Всё подготовлено: `vercel.json`, пароль на сайт, облачное хранилище. Осталось нажать несколько кнопок.

## Что нужно знать (коротко)

- На Vercel нельзя хранить данные в файле: серверные функции стирают его и не делят память. Поэтому данные кладём в **Upstash Redis** — его подключают кнопкой, писать ничего не нужно. Без него приложение работает, но данные пропадают при каждом перезапуске.
- Ссылка на Vercel **публичная**. В тестовой панели любой может стать создателем. Поэтому весь сайт закрыт **паролем** (`SITE_PASSWORD`). Пока пароль не задан, на боевом Vercel приложение показывает только «Нужен пароль».
- Это всё ещё заглушки без базы и без входа через Telegram: пароль общий, людей переключают вручную. Настоящий вход и база — следующий этап.

## Шаги

1. **Отправь код в GitHub** (репозиторий `vitos-sk/club` уже подключён):
   ```bash
   git add -A
   git commit -m "Подготовка к Vercel"
   git push
   ```
2. На vercel.com: **Add New → Project → Import** репозиторий `club`. Настройки не трогай: Next.js определится сам.
3. До нажатия Deploy открой **Environment Variables** и добавь:
   - `SITE_PASSWORD` — длинный пароль, который придумаешь ты;
   - `CREATOR_TG_ID` — твой Telegram id (необязательно; без него создатель — тестовый аккаунт).
4. Нажми **Deploy**. Подожди 1–2 минуты.
5. **Подключи хранилище**: в проекте открой **Storage → Create Database → Upstash (Redis)**, регион **Frankfurt (eu-central-1)**, нажми **Connect to Project**. Vercel сам добавит переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN`.
6. Открой **Deployments → ⋯ → Redeploy**, чтобы переменные подхватились.

## Проверка

1. Открой ссылку — появится «Закрытый клуб» и поле пароля. Введи `SITE_PASSWORD`.
2. Ты в Холле как №1 Создатель. Нажми жёлтую полоску «Тест» вверху: в блоке «Данные» должно быть **«Облачное хранилище (Upstash Redis): данные сохраняются»**.
3. Подтверди любую помощь, закрой страницу, открой снова: изменения на месте.

## Если что-то не так

| Что видишь | Причина | Что делать |
|---|---|---|
| «Нужен пароль» | не задан `SITE_PASSWORD` | Settings → Environment Variables → добавь → Redeploy |
| «Временное хранилище» в тестовой панели | не подключён Upstash | шаги 5–6 |
| Данные вернулись к начальным | в Upstash пусто или отключили | «Сбросить данные» в «Тест» запишет заново |
| Не сходится пароль | cookie от старого пароля | открой ссылку в окне инкогнито |

## Через консоль (если удобнее)

```bash
npx vercel          # первый раз попросит войти и привязать проект
npx vercel --prod   # боевая выкладка
```
Переменные добавляются командой `npx vercel env add SITE_PASSWORD`.

## Ограничения заглушек на Vercel

- Если два человека нажимают кнопки в одну секунду, последняя запись может затереть первую. Для проверки это терпимо, для живого клуба — нет: поэтому дальше нужна настоящая база (Supabase).
- Каждая страница читает всю «базу» из Upstash целиком (~50 КБ). Для теста быстро, для сотни людей уже нет.
